# Report incoherent functional mu3 support as divergence

## Background in Plain English — WHY

The functional Part II `mu3(A)` rule divides each sampled predictive mass by the current marginal predictive mass. The formal contract says positive sampled mass over a zero marginal predictive is an incoherent cavity and must diverge. The production rule uses a finite logarithm floor for that denominator, so the same case receives a large finite score and can look usable. This violates the documented support semantics and can hide an invalid parameter-message update.

## Outcomes / Acceptance Criteria — WHAT

1. `mu3_log_message` implements the exact support cases in `docs/DERIVATIONS.md` D6b.
   1.1. Zero sampled predictive mass contributes zero.
   1.2. Positive sampled mass outside exact goal support contributes negative infinity.
   1.3. Positive sampled mass over zero marginal predictive contributes positive infinity or another non-finite value that the status path classifies as divergence.
2. `mu3_importance_update` returns the diverged status for every NaN or positive-infinite functional score and never substitutes a finite floor or uniform weights.
3. `Engine.run` propagates that evaluator failure as `RunStatus.DIVERGED` and does not report a converged or budget-exhausted parameter update.
4. Direct tests compare production support-boundary scores with the independent D6b formula and cover float32.
5. Existing binary quadrature, finite-score, exact goal-zero, all-nonfinite-weight, replay, and uncomfortable-scale tests continue to pass.
6. Documentation and the paper inventory name the exact support contract and its direct test authority.

## Methodological Suggestions — HOW

These suggestions are optional. An implementer may choose another sound method that satisfies the numbered outcomes with equivalent evidence.

- Build the ratio term with explicit masks for sampled mass, goal support, and marginal-predictive support.
- Preserve non-finite sentinel values until `mu3_importance_update` assigns a truthful status.
- Keep dtype-derived guards inside the nonlinear state solve; do not use them to change the functional message support.

## Future work

`cff-in0q` owns propagation of the corrected stochastic status through the public agent lifecycle. Arbitrary active-support optimization for other stochastic factor families requires separate rule tickets.

## Definitions

- **Functional score:** The log value of the nonconjugate message evaluated at one sampled observation matrix.
- **Incoherent cavity:** Incoming and sampled beliefs assign incompatible support, so the variational ratio is undefined or infinite.
- **Marginal predictive:** The observation distribution `Abar zbar` formed from the current mean observation matrix and state belief.
