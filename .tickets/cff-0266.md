# Design the CFFG Studio workstation and its model library

## Background in Plain English — WHY

Cooper wants to build and run graphs from a remote computer and work on the same models as coding agents. Before building the app, choose where models live, who can change them, and how a user can tell which graphs compile and which performance numbers were measured.

## Outcomes / Acceptance Criteria — WHAT

1. A proposal on a dedicated branch names the stack, the remote route, and the ownership of models and revisions.
2. The proposal walks through a keyboard-only rSLDS edit, an agent handoff, a measured run, and a generated simulator.
3. It identifies reusable library code, missing capabilities, reviewable delivery tickets and measurable acceptance targets.
4. Cooper can open the proposal from agent-share.

## Methodological Suggestions — HOW

Use the compiler, edit codec, visualization, storage, and timing implementations as evidence. Verify the proposal using the ticket graph and a remote HTTP read.

## Future work

Implementation belongs to the Studio delivery epic and its linked tickets.

## Definitions

CFFG means constrained Forney-style factor graph. An rSLDS is a recurrent switching linear dynamical system. A revision is the complete saved state of a model at one accepted edit. Agent-share is the file service Cooper can reach over Tailscale.
