2. What changed since the July adversarial review

The July review found three trust failures: an incorrect transition-GFE cavity/ledger, a runtime that could return divergence as apparent success, and bundle serialization that could silently lose plate structure. It also found 300–4,000× chain slowdowns caused by flooding and Python dispatch.

Those were not papered over. The repository now has cavity-consistent transition GFE, explicit converged/exhausted/diverged/infeasible outcomes, dtype-scaled numerical guards, preserved plate bundles, shape-segmented arenas, topology-aware exact schedules, independent behavioral epistemics, and executable scalar-EF factor registration. This is the strongest reason for confidence in the project: adversarial findings have repeatedly become causal fixes with regression tests.

Performance moved correspondingly. Current scheduled HMM comparisons are roughly 15–28× a strict specialized ceiling rather than hundreds or thousands of times slower. The rSLDS cold setup defect fell from a 741-second median to 24 seconds with exact semantic parity. That is meaningful progress, not benchmark theater.

The course has nevertheless widened again. The project now carries a universal-factor epic, neural factors, nonlinear EP, tree rSLDS, destination softmax, structure learning, hierarchy, plates, visualization, glucose, and several performance branches at once. The next correction is therefore a breadth freeze, not another rescue.

3. Faithfulness to the two papers

What is faithful

Paper burdenRepository statusAssessment
Part I Eq. 8: node-local BFE plus edge-entropy overcounting corrections engine._make_bfe combines registered node terms and one correction per interior edge; tree tests check BFE = -log Z. Faithful for named exact families
Part I Eq. 25: replace selected local F terms with local G terms The compiler recognizes supported P-substitution composites; the ledger combines their GFE with ordinary nodes and shared corrections. Faithful for supported composites
Part II indirect state message / Newton solve The production solver uses the same stationary equation with a stronger gauge-reduced trust/globalization layer. Independent simplex minimization checks it. Faithful equation, sound robustness extension
Part II mu3(A) nonstandard functional message The functional, importance sampling, fixed-key replay, ESS failures, shared parameter KL, and quadrature anchors exist. Faithful machinery
Known-A direct policy inference / T-maze Policy marginals are pinned to the authors' Julia reference and the behavioral suite checks relevance, satiation, information gain, return, and the BFE ablation. Strong independent evidence
Paper warnings about non-convexity and stochastic estimates Limitations document local minima, Bethe approximation, optimistic bounds, importance noise, and truthful exhaustion. Mostly candid; explicitly name limit cycles too

The central gap

The repository implements mu3(A), but RollingAgent does not use it. The claimed Part II §7.1 T-maze learning reproduction plans with analytic moments of a Dirichlet belief and updates A from perceptual evidence only. Its own test says future-slice-to-A messages are absent.

This is not junk science. It is a principled and useful learned-A approximation, and it reproduces the qualitative learning curve. It is not the paper's complete unified parameter-message cycle. End behavior cannot substitute for the missing message path.

The minimum correction is to rename the experiment and narrow the README. The faithful correction is to make mu3 a first-class agent option with explicit PRNG state, refresh epochs, ESS/status propagation, checkpoint restore, and one end-to-end Part II trial-loop oracle.

Other boundaries that must stay explicit

  • The implemented CFFG constraint vocabulary is a subset: delta, naive mean field, selected P-substitution, and reserved moment matching. The papers' general structured factorization and form-constraint language is not universally executable.
  • The runtime uses separate compiled planning and filtering windows. That is a sensible receding-window realization, but not the paper's literal single model whose constraints change from P-substitution to data.
  • The general facing-node derivation in Part II is a derivational framework, not an implemented universal GFE rule. Each supported family still needs a specific derivation.
  • Hybrid mixture BFE and regime epistemic GFE are documented bounds. engine.bfe(state) # exact is therefore too broad as a public statement.
  • rSLDS is an extension built consistently with CFFG principles. It is not a validation target supplied by the CFFG papers.

5. Maintainability

What is healthy

  • The pure-Python IR is independent of JAX and is a durable source of truth.
  • The architecture change-path table correctly names authority, derived surfaces, tests, and documentation.
  • The test suite uses enumeration, quadrature, independent NumPy oracles, literature goldens, and hostile-input cases—not only self-parity.
  • Status semantics and scientific limitations are unusually honest.
  • The scalar exponential-family FactorKernel path genuinely allows a custom factor without central type-string branches.

What is structurally risky

SignalWhy it mattersBest seam
engine.py 3,816 lines Flooding, batched schedule, registerized scan, energy, and readout rebuild related input/parameter semantics independently. Per-arena group executors sharing gather, parameter subset, rule, and node-energy contracts.
compiler.py 2,316 lines One long transaction performs layout, family classification, composite recognition, lowering, packing, learning, and assembly. Topology/layout, typed classification, per-arena lowering, composites/learnables, final assembly.
Arena as one parallel-array schema Every new field creates a manual audit across engine and schedule consumers. Nested immutable arena views, migrated one family at a time.
rules.py 966 lines Ordinary discrete, categorical GFE, mu3 sampling, and transition GFE have different math and risk owners. Discrete, GFE, and mu3 modules behind compatibility imports.
rslds_fit.py 1,027 lines The new file exceeds the project's 1,000-line rule and mixes initialization, results/diagnostics, helpers, and orchestration. Move initialization to rslds_init.py; retain the linear fit loop.
Top-level cffg package exports almost nothing Users learn deep internal imports; a leftover hello() makes the 0.1 surface look unfinished. A small supported facade and one install-to-checkpoint example.

Do not perform a cosmetic file-splitting campaign. Characterize execution parity first, extract stable state/numeric primitives, split mathematical rule ownership, then unify per-arena execution contracts and compiler passes. Refactoring outer.py or redesigning statuses can wait.

7. The rewritten rSLDS roadmap

The rewrite is a real correction. Earlier work separately established fixed-generating-parameter inference, observed-only fitting, solver retry behavior, numerical cancellation repair, and cold setup. The newest source review then found that the authors' executable learner is narrower than the published source-specific model and that generator/learner default trees can differ. The new chain separates environment lock, a paper-equation adapter, preregistration, and final evidence.

What the chain can prove

  • same-generative-model predictive and recovery non-inferiority against an independently derived Gibbs implementation;
  • reproducibility across frozen seeds, diagnostics, and artifact hashes;
  • whether the current CFFG variational fitter is empirically competitive on the declared synthetic NASCAR protocol.

What it cannot prove

  • literal parity with the authors' executable learner, because that learner uses a narrower parameter family;
  • fidelity of CFFG's local variational messages and free-energy ledger to Parts I and II; that requires local equation-to-rule/energy oracles;
  • general rSLDS superiority, online-learning viability, or product value.

Rename the epic conclusion from “literature parity” to source-specific rSLDS empirical non-inferiority against an independently derived Gibbs reference. Strengthen adapter independence with an equation-level provenance ledger, clean-room tiny conditional oracles, frozen MCMC mixing diagnostics, and a compact direct production-message/energy audit. Then finish the chain and stop. Balanced trees are useful optional factor-library work, not a CFFG-paper or vision critical path.

9. Required course correction

  1. Correct claims before adding capability. Narrow README's “exact Bethe/Generalised free energy” to the declared ledger whose exact or bounded meaning depends on the factor family. Rename the Part II §7.1 learning experiment as a behavioral/analytic learned-A approximation. Explicitly document the two-window realization and Newton limit-cycle failure mode.
  2. Create one paper-faithfulness and minimum-usable-release gate. It should inventory every paper-defined constraint and Fig. 5 message, make mu3 first-class in the agent trial loop, add PRNG and checkpoint semantics, test one literal constraint-flip model against the two-window runtime, and give a newcomer one build→compile→run→inspect→ checkpoint path.
  3. Re-scope cff-ahps. “Universal factor library” contradicts the architecture's correct “extensible registry, not a universal solver” boundary. Replace it with a finite kernel-integration milestone: representative discrete, Gaussian, EF, and hybrid paths; shared execution/ledger contracts; loud unsupported combinations; hostile-input evidence.
  4. Freeze new family breadth until central execution seams improve. Do cff-209l and a bounded engine/compiler modularization sequence before nonlinear or neural factors. Characterization tests come before extraction.
  5. Prioritize visible runtime truth. Do vectorized readouts, honest resource estimation, compiled loop work, long-rollout convergence, and epistemic diagnostics before another model family. Split cff-wbhu if its ordinary loop and mixed-GFE controller cannot fit one reviewable PR. Separate cff-5edo's status/depth gating from its later warm-start speed work.
  6. Finish rSLDS confirmation, then make an evidence-based stop/go decision. Do not automatically roll into balanced-tree recurrence.
